# Дизайн прототипа 2.1

Основная ссылка Refero: Customer.io, стиль 80dfc59f-6542-4f24-bf35-02e294f51225. Сохранены светлый серый фон, белые поверхности, текст #00262b, тонкие границы, малые радиусы блоков и округлые кнопки. #abffae применяется к взаимодействиям и фокусу. Рабочая плотность адаптирована к таблицам лаборатории.

Ссылка структуры: Attio, экран 361d1d78-a133-43a7-b1ca-52a9ee163e15. Заимствованы боковая навигация, таблицы с фильтрами и ясная иерархия строки. Цвета Attio не переносились.

Ссылка последовательности: Refero flow 4186, Create project and activate. Заимствованы явное завершение действия, обновление активного контекста и короткое сообщение результата.

Решения: основные функции разделены по кабинетам на основе требований пользователя. Большие партии используют страницы по 50 строк. Данные заказчика скрыты в DOM рабочего задания исполнителя; настоящая серверная защита находится за пределами демоверсии. Логотип и все элементы интерфейса созданы средствами SVG/HTML/CSS; растровая графика не требуется.

Проверка: стартовый экран, рабочие кабинеты, частичная приёмка, обезличенные результаты и документ проверены в браузере. Логика регистрации, разрешений, повторов и снимков документа проверяется отдельно. Мобильные стили заданы медиазапросами.

Изменение 30.10.2026: по пожеланию пользователя статус окрашивает всю строку заявок, проб, заданий, реестра, хранения и версий документов. Основа Customer.io и структура Attio сохранены. Дополнительный источник — Refero Color Guide: приглушённые семантические поверхности, тёмный текст, предсказуемое затемнение при наведении. Цвет взаимодействий #abffae не используется как токен статуса.

Уточнение формы 30.10.2026: пользователь согласовал компактный множественный выбор испытаний, удаление цели, сохранение акта, отборщика и возврата, уточнение контакта, полный перечень клинических признаков и свободное дополнение. Сохранён существующий reference lock Customer.io / Attio. По Refero Craft Details Guide галочка и подпись образуют единую область нажатия; подписи постоянные, фокус видимый, поле телефона использует tel. В форме уменьшены отступы и высота полей; чекбоксы видов стоят в одной строке, признаки — в компактной сетке. Справочник показателей имеет поиск, две колонки и ограниченную высоту внутри компактного диалога. Для телефона и контактного лица сохраняется установленная модель доступа.

Выбранные виды применяются к каждой пробе, далее отдельной пробе можно назначить свой набор услуг. Инфекционная заявка допускает ПЦР, ИФА и количественные маститы вместе; генетическая заявка — заболевания, SNP и происхождение. Нумерация направлений остаётся раздельной, продукция использует свою форму исходных сведений. Для смешанной партии результаты и демонстрационный документ разделены на секции методов; проверка полноты и отчётность учитывают метод конкретного назначения.

Следующее уточнение пользователя: убрать ручной выбор раздела, показать все семь видов испытаний галочками первым компактным блоком; кнопки назначения подписать «Выбрать исследование», коды показывать отдельной подписью; для инфекционных проб заменить ручное обозначение автоматическим порядковым номером. Порядковые номера сохраняются при удалении соседних строк, новые строки получают следующий номер. Индивидуальный номер животного остаётся отдельным полем только для назначенных генетических исследований. Наименование продукции хранится в её дополнительных сведениях.

Одновременно выбранные направления определяются автоматически. До отправки это одна форма/черновик. При отправке назначения разделяются на связанные заявки инфекций, генетики животных и продукции, с сохранением общих сведений и связи исходных проб. Менеджер видит предупреждение об этом на шаге проверки и ссылки в карточке. Нумерация направлений и уникальная генетическая идентичность сохранены; старые зарегистрированные записи не перенумеровываются.

Уточнение 02.11.2026: обязательные поля отмечаются звёздочкой, ошибки выделяются у конкретного поля и перечисляются на шаге проверки. Список содержит переход на нужный шаг и страницу таблицы; после неудачной отправки фокус переходит к первому проблемному полю. Подсветка и сообщение исчезают при исправлении без перерисовки всей формы. Проверка отправки и интерфейс используют общий список ошибок из модели. Красный используется только для ошибок и обязательных отметок.
